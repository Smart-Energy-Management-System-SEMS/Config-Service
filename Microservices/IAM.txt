## Microservicio IAM (SEMS)

- Nombre: `iam-service` (`spring.application.name=iam-service`)
- Lenguaje/framework: `Java 21 + Spring Boot 3`
- Estado: `Solo local / En desarrollo`
- URL local:
  - Directo: `http://localhost:8080`
  - Vía gateway local nginx: `http://localhost:8081`
- URL deployada: `Pendiente (no definida en repo)`
- Base path sugerido: `/api/v1/iam` (a nivel gateway lógico)  
  Nota: internamente hoy expone `/api/v1/auth` y `/api/v1/users`.

---

## 1) Endpoints REST disponibles

### Auth

1. `POST /api/v1/auth/register`
- Path interno: `/api/v1/auth/register`
- Path gateway sugerido: `/api/v1/auth/register`
- Descripción: registro de usuario con rol inicial.
- Request:
```json
{
  "emailAddress": "user@demo.com",
  "password": "secret123",
  "role": "ADMIN"
}
```
- Response 200:
```json
{
  "token": "jwt",
  "userId": "uuid",
  "emailAddress": "user@demo.com",
  "roles": ["ADMIN"]
}
```
- Códigos: `200, 400, 401, 404, 409, 500`

2. `POST /api/v1/auth/login`
- Path interno: `/api/v1/auth/login`
- Path gateway: `/api/v1/auth/login`
- Descripción: login por email/password.
- Request:
```json
{
  "emailAddress": "user@demo.com",
  "password": "secret123"
}
```
- Response 200: mismo `LoginResponse`.
- Códigos: `200, 400, 401, 500`

3. `POST /api/v1/auth/google`
- Path interno: `/api/v1/auth/google`
- Path gateway: `/api/v1/auth/google`
- Descripción: login OAuth Google con `idToken`.
- Request:
```json
{
  "idToken": "google-id-token"
}
```
- Response 200: `LoginResponse`.
- Códigos: `200, 400, 401, 404, 500`

4. `GET /api/v1/auth/google/url`
- Path interno: `/api/v1/auth/google/url`
- Path gateway: `/api/v1/auth/google/url`
- Descripción: devuelve URL de autorización Google.
- Request body: no aplica.
- Response 200:
```json
{
  "authorizationUrl": "https://accounts.google.com/o/oauth2/v2/auth?..."
}
```
- Códigos: `200, 500`

5. `GET /api/v1/auth/google/callback?code=...`
- Path interno: `/api/v1/auth/google/callback`
- Path gateway: `/api/v1/auth/google/callback`
- Descripción: callback OAuth, intercambia `code` por token Google e inicia sesión.
- Request body: no aplica (usa query param `code`).
- Response 200: `LoginResponse`.
- Códigos: `200, 400, 401, 500`

### Users

6. `GET /api/v1/users/me`
- Path interno: `/api/v1/users/me`
- Path gateway: `/api/v1/users/me`
- Descripción: datos del usuario autenticado.
- Request body: no aplica.
- Response 200:
```json
{
  "userId": "uuid",
  "emailAddress": "user@demo.com",
  "roles": ["ADMIN"]
}
```
- Códigos: `200, 401, 404, 500`

7. `GET /api/v1/users`
- Path interno: `/api/v1/users`
- Path gateway: `/api/v1/users`
- Descripción: lista todos los usuarios.
- Request body: no aplica.
- Response 200: lista de `UserResource`.
- Códigos: `200, 401, 403, 500`

8. `POST /api/v1/users/{userId}/roles`
- Path interno: `/api/v1/users/{userId}/roles`
- Path gateway: `/api/v1/users/{userId}/roles`
- Descripción: asigna rol a usuario.
- Request:
```json
{
  "role": "ADMIN"
}
```
- Response 200: vacío.
- Códigos: `200, 400, 401, 403, 404, 500`

### Health

9. `GET /actuator/health`
- Path interno: `/actuator/health`
- Path gateway sugerido: `/iam/health` o `/actuator/health` (interno)
- Descripción: health check del servicio.
- Response 200 (ejemplo):
```json
{
  "status": "UP"
}
```
- Códigos: `200, 503`

- Health check recomendado: `GET /actuator/health`

---

## 3) Reglas de seguridad

- Públicos:
  - `POST /api/v1/auth/**`
  - `GET /actuator/health`
- Requieren JWT:
  - `GET /api/v1/users/me`
  - `GET /api/v1/users`
  - `POST /api/v1/users/{userId}/roles`
- Roles:
  - `GET /api/v1/users` -> `ADMIN`
  - `POST /api/v1/users/{userId}/roles` -> `ADMIN`
- Headers:
  - `Authorization: Bearer <token>` (protegidos)
  - `Content-Type: application/json` (POST con body)

## 4) Integración con Kafka

- Produce:
  - `iam.user.registered`
  - `iam.user.logged-in`
  - `iam.role.assigned`
- Consume:
  - `iam.role-assignment.requested`

### Eventos publicados

1. `iam.user.registered`
```json
{
  "eventType": "iam.user.registered",
  "userId": "uuid",
  "emailAddress": "user@demo.com",
  "role": "RESIDENT|ADMIN",
  "occurredAt": "ISO-8601"
}
```

2. `iam.user.logged-in`
```json
{
  "eventType": "iam.user.logged-in",
  "userId": "uuid",
  "emailAddress": "user@demo.com",
  "occurredAt": "ISO-8601"
}
```

3. `iam.role.assigned`
```json
{
  "eventType": "iam.role.assigned",
  "userId": "uuid",
  "role": "ADMIN|RESIDENT",
  "occurredAt": "ISO-8601"
}
```

### Evento escuchado

- `iam.role-assignment.requested`
```json
{
  "userId": "uuid",
  "role": "ADMIN|RESIDENT"
}
```
