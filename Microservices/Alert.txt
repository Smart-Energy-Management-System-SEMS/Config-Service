**Microservicio SEMS - Alert Service**

- Nombre: `alert-service`
- Lenguaje/framework: Go + Gin
- Estado: En desarrollo / local
- URL local: `http://localhost:8085`
- URL deployada: Pendiente
- Base path sugerido: `/api/v1/alerts-service` (recomendado en Gateway)  
Path interno real del microservicio: `/api/v1/*`

## 1) Endpoints REST disponibles

1. `GET`  
Path interno: `/api/v1/health`  
Path Gateway sugerido: `/api/v1/alerts-service/health`  
Descripción: Health check del servicio  
Request body: No aplica  
Response:
```json
{"status":"ok","service":"alert-service"}
```  
Códigos: `200`

2. `GET`  
Path interno: `/api/v1/alerts`  
Path Gateway: `/api/v1/alerts-service/alerts`  
Descripción: Listar todas las alertas  
Request: No aplica  
Response: `AlertResponse[]`  
Códigos: `200`, `500`

3. `GET`  
Path interno: `/api/v1/alerts/:id`  
Path Gateway: `/api/v1/alerts-service/alerts/:id`  
Descripción: Obtener alerta por ID  
Request: No aplica  
Response: `AlertResponse`  
Códigos: `200`, `400`, `404`, `500`

4. `GET`  
Path interno: `/api/v1/users/:userId/alerts`  
Path Gateway: `/api/v1/alerts-service/users/:userId/alerts`  
Descripción: Listar alertas por usuario  
Response: `AlertResponse[]`  
Códigos: `200`, `400`, `500`

5. `POST`  
Path interno: `/api/v1/alerts`  
Path Gateway: `/api/v1/alerts-service/alerts`  
Descripción: Crear alerta manual  
Request:
```json
{
  "user_id":"uuid",
  "device_id":"uuid",
  "threshold_id":"uuid|null",
  "inactivity_rule_id":"uuid|null",
  "alert_type":"string",
  "title":"string",
  "message":"string",
  "severity":"string",
  "status":"string",
  "triggered_at":"RFC3339|null"
}
```  
Response: `AlertResponse`  
Códigos: `201`, `400`, `500`

6. `PATCH`  
Path interno: `/api/v1/alerts/:id/status`  
Path Gateway: `/api/v1/alerts-service/alerts/:id/status`  
Descripción: Actualizar estado de alerta  
Request:
```json
{"status":"string","resolved_at":"RFC3339|null"}
```  
Response: vacío  
Códigos: `204`, `400`, `404`, `500`

7. `POST`  
Path interno: `/api/v1/thresholds`  
Path Gateway: `/api/v1/alerts-service/thresholds`  
Descripción: Crear umbral  
Request:
```json
{
  "user_id":"uuid",
  "device_id":"uuid",
  "threshold_name":"string",
  "metric":"string",
  "operator":"string",
  "threshold_value":0,
  "active":true
}
```  
Response: `ThresholdResponse`  
Códigos: `201`, `400`, `500`

8. `GET`  
Path interno: `/api/v1/users/:userId/thresholds`  
Path Gateway: `/api/v1/alerts-service/users/:userId/thresholds`  
Descripción: Umbrales por usuario  
Response: `ThresholdResponse[]`  
Códigos: `200`, `400`, `500`

9. `POST`  
Path interno: `/api/v1/inactivity-rules`  
Path Gateway: `/api/v1/alerts-service/inactivity-rules`  
Descripción: Crear regla de inactividad  
Request:
```json
{
  "user_id":"uuid",
  "device_id":"uuid",
  "rule_name":"string",
  "max_inactive_minutes":10,
  "active":true
}
```  
Response: `InactivityRuleResponse`  
Códigos: `201`, `400`, `500`

10. `GET`  
Path interno: `/api/v1/users/:userId/inactivity-rules`  
Path Gateway: `/api/v1/alerts-service/users/:userId/inactivity-rules`  
Descripción: Reglas por usuario  
Response: `InactivityRuleResponse[]`  
Códigos: `200`, `400`, `500`

11. `POST`  
Path interno: `/api/v1/notification-preferences`  
Path Gateway: `/api/v1/alerts-service/notification-preferences`  
Descripción: Crear preferencia de notificación  
Request:
```json
{
  "user_id":"uuid",
  "channel":"email|sms",
  "enabled":true,
  "min_severity":"low|medium|high|critical",
  "quiet_hours_start":"HH:mm",
  "quiet_hours_end":"HH:mm"
}
```  
Response: `NotificationPreferenceResponse`  
Códigos: `201`, `400`, `500`

12. `GET`  
Path interno: `/api/v1/users/:userId/notification-preferences`  
Path Gateway: `/api/v1/alerts-service/users/:userId/notification-preferences`  
Descripción: Preferencias por usuario  
Response: `NotificationPreferenceResponse[]`  
Códigos: `200`, `400`, `500`

Error estándar:
```json
{"error":"mensaje"}
```

## 2) Configuración para API Gateway

- Nombre lógico: `alert-service`
- Host local: `localhost`
- Puerto local: `8085`
- URL deployada: Pendiente
- Base path en Gateway (sugerido): `/api/v1/alerts-service`
- Health check recomendado: `GET /api/v1/alerts-service/health` (mapea a `/api/v1/health`)

## 3) Reglas de seguridad

- JWT requerido: No implementado en este microservicio (actualmente público)
- Endpoints públicos: Todos los endpoints listados
- Roles: No implementado
- Headers requeridos:
  - `Content-Type: application/json` en `POST/PATCH`
  - `Authorization: Bearer <token>`: pendiente (ideal implementarlo en Gateway)

## 4) Integración Kafka

- Topics que produce: No hay productor Kafka implementado
- Topics que consume:
  - `energy.consumption.recorded` (por `KAFKA_CONSUMPTION_TOPIC` o `KAFKA_TOPIC_DEVICE_READING_CREATED`)
- Eventos publicados: Pendiente
- Eventos escuchados: evento de consumo energético
- Payload escuchado:
```json
{
  "user_id":"uuid",
  "device_id":"uuid",
  "metric":"kwh",
  "value":15.5,
  "recorded_at":"2026-05-26T00:00:00Z"
}
```

## 5) Variables de entorno necesarias

- `SERVER_PORT`
- `DATABASE_URL`
- `KAFKA_BROKERS`
- `KAFKA_CONSUMER_GROUP` (o `KAFKA_GROUP_ID`)
- `KAFKA_CONSUMPTION_TOPIC` (o `KAFKA_TOPIC_DEVICE_READING_CREATED`)
- `TWILIO_ACCOUNT_SID`
- `TWILIO_API_KEY`
- `TWILIO_API_SECRET`
- `TWILIO_PHONE_NUMBER`
- `MAIL_HOST`
- `MAIL_PORT`
- `MAIL_USERNAME`
- `MAIL_PASSWORD`
- `MAIL_FROM`

## 6) Dependencias externas

- PostgreSQL/Neon: persistencia de alertas, reglas, preferencias y logs
- Kafka: consumo de eventos de consumo
- Twilio: envío de SMS
- Gmail SMTP: envío de emails
