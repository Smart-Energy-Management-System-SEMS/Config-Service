### Request/Response contracts (resumen)
- `CreateDeviceResource`: `externalDeviceCode, userId, deviceName, deviceType, brand?, model?, connectionProtocol`
- `UpdateDeviceResource`: `deviceName, deviceType, brand?, model?, connectionProtocol`
- `UpdateDeviceStatusResource`: `status`
- `CreateDeviceBindingResource`: `userId, homeId?`
- `CreateDeviceConfigurationResource`: `configKey, configValue?`
- `UpdateDeviceConfigurationResource`: `configValue?`
- `CreateDeviceEventResource`: `eventType, description?, occurredAt?`

Error estándar:
```json
{ "code": "VALIDATION_ERROR|NOT_FOUND|CONFLICT|INTERNAL_ERROR", "message": "..." }
```

## 3) Reglas de seguridad
- **Implementación actual del microservicio**: no tiene middleware JWT/roles.
- **Público recomendado**:
  - `GET /api/v1/health/device-management`
- **JWT requerido recomendado (en Gateway)**:
  - todos los demás endpoints.
- **Roles**:
  - no definidos en este microservicio (`pendiente`).
- **Headers requeridos**:
  - `Authorization: Bearer <token>` (rutas protegidas, validado en Gateway)
  - `Content-Type: application/json` (POST/PUT/PATCH)
  - `Accept: application/json`

## 4) Integración con Kafka
### Topics que produce
- `device.registered`
- `device.status.updated`
- `device.linked`
- `device.unlinked`
- `device.configuration.updated`
- `device.event.recorded`

### Topics que consume
- Ninguno en runtime actual (hay código de consumer, pero no está conectado en `main`).

### Eventos publicados y payload
Envelope común:
```json
{
  "eventId": "uuid",
  "eventType": "string",
  "deviceId": "uuid",
  "userId": "uuid",
  "occurredAt": "ISO8601",
  "payload": {}
}
```

Payload por tipo:
- `DEVICE_REGISTERED`: `{ externalDeviceCode, deviceType, status }`
- `DEVICE_STATUS_UPDATED`: `{ previousStatus, newStatus }` (en delete puede venir solo `newStatus`)
- `DEVICE_LINKED`: `{ bindingId, homeId }`
- `DEVICE_UNLINKED`: `{ bindingId, unlinkedAt }`
- `DEVICE_CONFIGURATION_UPDATED`: `{ configurationId, configKey }`
- `DEVICE_EVENT_RECORDED`: `{ eventId, eventType }`

### Estado Kafka actual
- `KAFKA_ENABLED=false` por defecto, por lo que en local el servicio **no publica** mientras Kafka esté apagado.
