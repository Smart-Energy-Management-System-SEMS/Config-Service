# Inventario técnico - IAM Service

## 1. Identificación
- Servicio: `iam-service`
- Lenguaje/framework: `Java 21 + Spring Boot 3.3.4` (`spring-boot-starter-web`, `security`, `actuator`, `data-jpa`, `spring-kafka`)
- Archivo principal: `src/main/java/com/sems/SemsIamApplication.java`
- Archivos de rutas/controladores: `src/main/java/com/sems/iam/interfaces/rest/AuthenticationController.java`, `UserController.java`, `RoleController.java`, `HealthController.java`
- Archivos de configuración: `src/main/resources/application.properties`, `.env`, `.env.example`, `docker-compose.yml`, `Dockerfile`, `src/main/java/com/sems/iam/infrastructure/authorization/sfs/configuration/SecurityConfiguration.java`, `src/main/java/com/sems/iam/infrastructure/config/ConfigServiceEnvironmentPostProcessor.java`, `src/main/java/com/sems/iam/infrastructure/messaging/kafka/configuration/KafkaTopicsProperties.java`, `KafkaTopicConfiguration.java`

## 2. HTTP / Red
- Puerto real: `8082` local por `.env` + `server.port=${SERVER_PORT:${PORT:8080}}`; `8080` dentro de Docker Compose (`SERVER_PORT: 8080`, contenedor `:8080`, publish `${IAM_PORT:-8080}:8080`)
- Puerto por defecto: `8080`
- Variable de puerto: `SERVER_PORT` con fallback a `PORT`
- Host: `No encontrado` para binding HTTP (`server.address` no definido). URL pública configurada: `service.public-base-url=${IAM_DEPLOY_URL:http://localhost:8082}`
- Prefix/base path: `No hay prefix global configurable`. Rutas REST hardcodeadas con `/api/v1/...`
- Health endpoints: `/health`, `/actuator/health`, `/actuator/health/liveness`, `/actuator/health/readiness`
- CORS: `Sí`. Orígenes: `http://localhost:3000,http://localhost:5173`; métodos: `GET, POST, PUT, PATCH, DELETE, OPTIONS`; headers: `Authorization, Content-Type, Accept, Origin`

## 8. Inconsistencias internas encontradas
- Puerto inconsistente entre fuentes: `application.properties` default `8080`; `.env` usa `SERVER_PORT=8082`; `.env.example` define `PORT=8080` y `SERVER_PORT=8082`; `Dockerfile` expone `8080`; `docker-compose.yml` fuerza `SERVER_PORT=8080` y publica `${IAM_PORT:-8080}:8080`.
- No existe `API_BASE_PATH` ni `server.servlet.context-path`; el prefix REST está hardcodeado en controladores (`/api/v1/auth`, `/api/v1/users`).
- El micro expone health real en código (`/health`) y Actuator (`/actuator/health...`), pero `Dockerfile` y `docker-compose.yml` no definen `HEALTHCHECK`/`healthcheck`.
- Variables Kafka duplicadas para bootstrap: `KAFKA_BROKERS` y `KAFKA_BOOTSTRAP_SERVERS` apuntan al mismo concepto; el código prioriza `KAFKA_BROKERS` y luego `KAFKA_BOOTSTRAP_SERVERS`.
- Variantes Docker Kafka inconsistentes: `.env` usa `kafka:29092`, pero `.env.example` y `docker-compose.yml` usan `kafka:9092`.
- Variables Kafka presentes pero no usadas por la app Spring para conexión: `KAFKA_HOST` y `KAFKA_PORT`.
- Variables Kafka auxiliares solo para Compose/interpolación, no leídas directamente por Spring: `KAFKA_BROKERS_DOCKER`, `KAFKA_BOOTSTRAP_SERVERS_DOCKER`.
- `.env` actual no define `TOPIC_IAM_*`; por lo tanto, localmente los topics reales caen en los defaults de `application.properties`.
- No encontré topics hardcodeados distintos a los defaults configurados.
- No encontré topics legacy todavía usados.
- No encontré topics duplicados entre publish/consume.
- No encontré consumers registrados sin handler.
- No encontré publishers definidos sin uso.
- No encontré endpoints definidos pero no registrados.
- No encontré handlers creados pero no conectados.
- El micro sí puede sobrescribir `server.port`, `spring.kafka.*`, `topics.*` y `service.public-base-url` desde `CONFIG_SERVICE_URL`, pero ese valor externo no es verificable desde este repo.
