# Inventario técnico - Subscriptions Service

## 1. Identificación
- Servicio: `subscriptions-service` (Subscriptions Service)
- Lenguaje/framework: Go + Gin (`github.com/gin-gonic/gin`), GORM, `segmentio/kafka-go`
- Archivo principal: `main.go`
- Archivos de rutas/controladores: `subscriptions/router.go`, `subscriptions/interfaces/rest/controllers/subscription_controller.go`
- Archivos de configuración: `subscriptions/infrastructure/configuration/config.go`, `.env`, `.env.example`, `Dockerfile`, `docker-compose.yml`

## 2. HTTP / Red
- Puerto real: `18083` en ejecución local con el `.env` actual. En Docker Compose el proceso escucha en `8080` y se expone al host como `8083` por `APP_PORT` (`${APP_PORT:-8083}:8080`)
- Puerto por defecto: `8080`
- Variable de puerto: precedencia real en código `PORT` > `SERVER_PORT` > `remote.ServerPort` > `8080`
- Host: No encontrado explícito. Inferido: bind en todas las interfaces por `r.Run(":"+cfg.ServerPort)`
- Prefix/base path: `/api/v1`
- Health endpoints: `/health`, `/api/v1/health`
- CORS: Sí. Permite `http://localhost:3000` y `http://localhost:5173`; métodos `GET, POST, PUT, PATCH, DELETE, OPTIONS`; `Allow-Credentials=true`

## 8. Inconsistencias internas encontradas
- Puerto inconsistente entre fuentes:
  - `.env`: `SERVER_PORT=18083`
  - `.env.example`: `PORT=8080` y `SERVER_PORT=8080`
  - `Dockerfile`: `PORT=8080`
  - `docker-compose.yml`: `PORT=8080`, `SERVER_PORT=8080`, host `APP_PORT` default `8083`
  - Real por precedencia de código: local actual `18083`; en contenedor `8080`
- Hay doble variable para brokers: `KAFKA_BROKERS` y `KAFKA_BOOTSTRAP_SERVERS`. Ambas se soportan; esto duplica configuración
- `KAFKA_CLIENT_ID` se carga en config y se guarda en `Publisher`, pero el publisher no lo aplica al `kafka.Writer`; efectivamente queda sin uso real en la publicación
- `KafkaBootstrapServer` existe en `AppConfig`, pero `main.go` pasa `cfg.KafkaBrokers` al publisher; el campo individual no se usa directamente fuera de la carga/fallback
- No hay healthcheck del servicio `subscriptions-service` en `Dockerfile` ni en `docker-compose.yml`; solo existen endpoints HTTP de health en código
- No existe variable `API_BASE_PATH`; el prefijo `/api/v1` está hardcodeado en `subscriptions/router.go`
- Los topics `KAFKA_TOPIC_SUBSCRIPTION_*` no están definidos en `.env` actual; el runtime local depende de defaults de código o de override remoto por `CONFIG_SERVICE_URL`
- No se encontraron consumers Kafka registrados
- No se encontraron topics legacy usados
- No se encontraron publishers definidos pero desconectados
- No se encontraron endpoints definidos pero no registrados en el router
- No se encontraron handlers HTTP creados pero no conectados
