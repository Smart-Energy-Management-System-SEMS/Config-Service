## 8. Inconsistencias internas encontradas
- Puerto inconsistente: código usa default `8085`, `.env` y `docker-compose` usan `8086`, `.env.example` además declara `PORT=8080`, y `Dockerfile` hace `EXPOSE 8080`.
- Variables de puerto duplicadas: el código prioriza `PORT` sobre `SERVER_PORT`; `.env` solo define `SERVER_PORT`, `.env.example` define `PORT=8080` y `SERVER_PORT=8086`.
- Health check inconsistente a nivel de despliegue: el código expone `/health` y `/api/v1/health`, pero `Dockerfile` y `docker-compose.yml` no definen `HEALTHCHECK`.
- Prefix potencialmente sobrescribible: el código usa `API_BASE_PATH` local, pero `config_service_client.go` puede reemplazarlo desde `CONFIG_SERVICE_URL`; el valor local real puede variar si ese servicio responde.
- Convención Kafka inconsistente: `.env` usa variables legacy `KAFKA_*_TOPIC`; `.env.example` usa variables oficiales `KAFKA_TOPIC_*`; el código soporta ambas.
- Variable Kafka existente pero no usada: `KAFKA_PAYMENT_REQUESTED_TOPIC` está en `.env`, pero no aparece en el código.
- Variables Kafka declaradas para ejemplo pero no leídas por este micro: `KAFKA_SECURITY_PROTOCOL`, `KAFKA_SASL_MECHANISM`, `KAFKA_USERNAME`, `KAFKA_PASSWORD`.
- No encontré topics hardcodeados con nombres distintos al `.env`; los nombres usados por productor, consumidor y `docker-compose` coinciden.
- No encontré topics duplicados activos; los 7 topics configurados son únicos.
- No encontré consumers registrados sin handler.
- No encontré publishers definidos pero totalmente sin uso.
- No encontré endpoints definidos pero no registrados.
- No encontré handlers HTTP creados pero no conectados.
- Los handlers de `subscription.created` y `subscription.cancelled` sí están conectados, pero actualmente solo hacen log y no ejecutan lógica adicional.
