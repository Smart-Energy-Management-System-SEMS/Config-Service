1. Nombre del microservicio:
`alert-service`

2. Bounded Context al que pertenece:
`Alert Management` (alertas, umbrales, reglas de inactividad, preferencias y notificaciones)

3. Puerto local usado:
`8085` (`SERVER_PORT`; fallback `8080`)

4. Base URL local:
`http://localhost:8085`

5. Base URL esperada para deploy:
`https://<alert-service-host>`

6. Endpoints principales expuestos al API Gateway:
- `GET /api/v1/alerts`
- `GET /api/v1/alerts/:id`
- `GET /api/v1/users/:userId/alerts`
- `POST /api/v1/alerts`
- `PATCH /api/v1/alerts/:id/status`
- `POST /api/v1/thresholds`
- `GET /api/v1/users/:userId/thresholds`
- `POST /api/v1/inactivity-rules`
- `GET /api/v1/users/:userId/inactivity-rules`
- `POST /api/v1/notification-preferences`
- `GET /api/v1/users/:userId/notification-preferences`
- `POST /api/v1/kafka/publish-test`

7. Prefijo base de rutas:
`/api/v1`

8. Variables de entorno necesarias:
- `SERVER_PORT`
- `DATABASE_URL`
- `KAFKA_BROKERS`
- `KAFKA_CONSUMER_GROUP`
- `KAFKA_GROUP_ID`
- `KAFKA_CONSUMPTION_TOPIC`
- `KAFKA_TOPIC_DEVICE_READING_CREATED`
- `MAIL_HOST`
- `MAIL_PORT`
- `MAIL_USERNAME`
- `MAIL_PASSWORD`
- `MAIL_FROM`
- `TWILIO_ACCOUNT_SID`
- `TWILIO_API_KEY`
- `TWILIO_API_SECRET`
- `TWILIO_PHONE_NUMBER`

9. Variables que son secretas y NO deben exponerse desde el Config Service:
- `DATABASE_URL`
- `TWILIO_ACCOUNT_SID`
- `TWILIO_API_KEY`
- `TWILIO_API_SECRET`
- `MAIL_USERNAME`
- `MAIL_PASSWORD`

10. Configuracion Kafka usada:
- bootstrap servers: `KAFKA_BROKERS`
- security protocol: `PLAINTEXT` en local/docker
- topics que consume:
  - `energy.consumption.recorded`
- consumer group: `alert-service-group`

11. Servicios externos que usa:
- Twilio
- SMTP
- Kafka broker
- PostgreSQL

12. Base de datos usada:
- motor: PostgreSQL
- variables de conexion: `DATABASE_URL`

13. Dependencias de otros microservicios:
- Dependencia asincrona por Kafka desde eventos de consumo energetico.
