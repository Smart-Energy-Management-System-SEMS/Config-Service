1. Nombre del microservicio:  
`device-management-service` (Device Management Service)

2. Bounded Context al que pertenece:  
`Device Management` (SEMS)

3. Puerto local usado:  
`8083` (default local)

4. Base URL local:  
`http://localhost:8083/api/v1/device-management`

5. Base URL esperada para deploy:  
`https://<host-del-entorno>/api/v1/device-management`  
(en Render el host viene de `RENDER_EXTERNAL_URL`)

6. Endpoints principales expuestos al API Gateway:  
- `GET /api/v1/device-management/health`  
- `POST /api/v1/device-management/devices`  
- `GET /api/v1/device-management/devices`  
- `GET /api/v1/device-management/devices/:deviceId`  
- `GET /api/v1/device-management/users/:userId/devices`  
- `PUT /api/v1/device-management/devices/:deviceId`  
- `PATCH /api/v1/device-management/devices/:deviceId/status`  
- `DELETE /api/v1/device-management/devices/:deviceId`  
- `POST /api/v1/device-management/devices/:deviceId/bindings`  
- `GET /api/v1/device-management/devices/:deviceId/bindings`  
- `GET /api/v1/device-management/users/:userId/bindings`  
- `PATCH /api/v1/device-management/bindings/:bindingId/unlink`  
- `POST /api/v1/device-management/devices/:deviceId/configurations`  
- `GET /api/v1/device-management/devices/:deviceId/configurations`  
- `PUT /api/v1/device-management/configurations/:configurationId`  
- `POST /api/v1/device-management/devices/:deviceId/events`  
- `GET /api/v1/device-management/devices/:deviceId/events`

7. Prefijo base de rutas:  
`/api/v1/device-management`

8. Variables de entorno necesarias:  
- `PORT`  
- `APP_ENV`  
- `DATABASE_URL`  
- `DB_DRIVER`  
- `AUTO_MIGRATE`  
- `KAFKA_BROKERS`  
- `KAFKA_CLIENT_ID`  
- `KAFKA_CONSUMER_GROUP`  
- `API_GATEWAY_ALLOWED_ORIGIN`  
- `CORS_ALLOWED_ORIGINS`  
- (operativas deploy/keepalive) `KEEP_ALIVE_ENABLED`, `KEEP_ALIVE_INTERVAL_SECONDS`, `KEEP_ALIVE_PATH`, `RENDER_EXTERNAL_URL`, `KEEP_ALIVE_URL`

9. Variables que son secretas y NO deben exponerse desde el Config Service:  
- `DATABASE_URL` (contiene credenciales)  
- Cualquier futura credencial Kafka (usuario/password/certs SASL-SSL, si se agrega)

10. Configuración Kafka usada:  
- bootstrap servers: `KAFKA_BROKERS` (default `localhost:9092`)  
- security protocol: no definido explícitamente  
- SASL mechanism: no definido  
- topics que produce:  
  - `device.registered`  
  - `device.status.updated`  
  - `device.linked`  
  - `device.unlinked`  
  - `device.configuration.updated`  
  - `device.event.recorded`  
- topics que consume: ninguno activo en runtime actual  
- consumer group: `KAFKA_CONSUMER_GROUP` (`device-management-group`, configurado)

11. Servicios externos que usa:  
- PostgreSQL (Neon)  
- Apache Kafka broker

12. Base de datos usada:  
- motor: PostgreSQL  
- nombre de base de datos: viene dentro de `DATABASE_URL` (ejemplo: `neondb`)  
- variables de conexión: `DATABASE_URL`, `DB_DRIVER`

13. Dependencias de otros microservicios:  
- No hay llamadas HTTP/gRPC directas a otros microservicios en este repo.  
- Sí hay dependencia de integración asíncrona por eventos Kafka (publicador).

14. Configuración que actualmente se repite y debería moverse al Config Service:  
- `APP_ENV`, `PORT`, `AUTO_MIGRATE`, `DB_DRIVER`  
- `KAFKA_BROKERS`, `KAFKA_CLIENT_ID`, `KAFKA_CONSUMER_GROUP`  
- `API_GATEWAY_ALLOWED_ORIGIN`, `CORS_ALLOWED_ORIGINS`  
- `KEEP_ALIVE_*` (si se estandariza entre servicios)  
- metadata de ruteo: prefijo `/api/v1/device-management` y base URL por entorno

15. Recomendación final de cómo debería registrarse este microservicio en el Config Service:  
Registrar `device-management-service` con:
- metadata: `serviceName`, `boundedContext`, `routePrefix`, `healthPath`
- endpoints públicos para gateway (lista anterior)
- configuración pública por entorno (port, cors, kafka brokers/client/group, flags)
- secretos referenciados por key vault/secret manager (`DATABASE_URL`, credenciales sensibles futuras)
- bloque Kafka separado entre `producerTopics` y `consumerTopics` (hoy `consumerTopics=[]`)
